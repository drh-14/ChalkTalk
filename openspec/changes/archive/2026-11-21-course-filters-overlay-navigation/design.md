## Decisions

- **Actual UI styling is authoritative.** Capture baseline real-browser screenshots of current UI at320/390/1280px before edits, using mocked APIs. Reuse existing product components/tokens/button/menu/filter styles; mockups guide only placement and interaction, not fonts/colors/radii/content/icons. Compare actual before/after screenshots and reject unrequested aesthetic drift. Minimal responsive spacing required to fit320px is allowed within existing tokens; raise any unavoidable material fit tradeoff before implementation.
- Reuse the existing filter subtree inside a locally owned nonmodal dialog/popover in Discussion. Place its trigger immediately after Search. Remove course-filter-panel/desktop pull tab/mobile collapse strip, obsolete useFilterPanel and their CSS. Keep FilterSection summaries, existing controls, routing/filter persistence and staff Duplicates entry; opening itself never fetches the feed.
- **Latest approved toolbar refinement:** Desktop shows the full Search field with Filters immediately to its right and New post reachable without overflow. At <=850px use one row of Search icon, New post icon, then text Filters. The Search icon exposes expanded/controls state and reveals the search field beneath that row, focuses it, preserves query when closed/reopened, and closes with Escape returning focus to Search. The existing `/` shortcut reveals/focuses mobile search. Keep icon buttons touch-friendly (44px) and accessible names; use existing line-icon styling. Search stays available through breakpoint changes without hiding focused input.
- Closed on fresh discussion mount; state not persisted. Preserve selected filters when opening/closing and close on route/course departure. Obsolete size localStorage entries are ignored, not deleted.
- Anchor the overlay's right edge to Filters, max 330px wide with 16px viewport margins and height capped by available viewport space (desktop up to 590px; mobile up to 540px). Recompute on viewport resize/orientation/scroll; prefer below trigger, flip above when it offers more usable room, clamp to viewport. A fixed header/close control remains outside the internally scrolling filter body. No content reflow, backdrop or page-width increase. Existing no-dependency DOM measurement/ref conventions suffice; no shared overlay framework.
- Use native trigger/close buttons, aria-expanded/controls and a labelled nonmodal dialog. On explicit open focus the first usable filter control; Escape or close returns focus to the trigger. Outside pointer closes without stealing focus from its intended target. Normal Tab can leave the nonmodal panel; do not trap focus or mark background inert. No old resize separator or yellow resize outline remains.
- At <=850px CourseFrame renders a native button and ordinary links for a current-section dropdown, generated from the SAME existing tabs/visibility data (including Thread unread count). Existing code currently maps six tabs; do not newly hide/show sections by role. Current nested resources routes map Resources; course-session maps Collaboration. Retain same-document follow/beforeLeave guards, modified-click behavior and heading focus after navigation. Escape/explicit close returns to section trigger; outside click closes. Desktop retains the same section choices and guards but keeps them on the logo row; use the same current-section dropdown immediately beside All courses when natural full-row width does not fit, preserving accessible focus when resizing. Hide inactive navigation variant from accessibility/keyboard traversal and preserve focus safely across breakpoint changes.
- AppBar gets only the small presentational slot/order adjustment needed to put All courses beside the wordmark on phones. Preserve notification/avatar controls, course status/switcher and main's full-title tooltip. Mobile course title and section dropdown share the next row, truncating only the name, not controls; targets44px where practical, no horizontal overflow at 320/390px. Other AppBar consumers unchanged.
- Replace old resize tests with overlay tests rather than retaining contradictory behavior. Preserve useful no-refetch/storage/filter-selection assertions. Extend current browser harness (mocked API) for header routes/role states; screenshot every affected state.

## Risks / Trade-offs

- Overlay temporarily covers post/detail content → explicit close, outside/Escape dismissal and no feed shift; intentional approved tradeoff versus permanent columns.
- Nonmodal mobile overlay offers less isolation than a modal → fixed close header, viewport bounds/internal scroll; avoids backdrop and retains context.
- Small viewport/soft keyboard can reduce available room → clamp measured viewport and keep header reachable; verify landscape and320px.
- Main has overlapping responsive changes → integrate through supported gate workflow after apply handoff; preserve PR269 behavior and rerun responsive-course-ui browser suite.
- Changing navigation markup can bypass draft guards or lose current-state semantics → reuse tabs/follow handler; test denied/accepted navigation and nested routes.
- Gate-added fixes may create multiple commits → preserve complete history in archive refs, supported custody/handoff then tree-equivalent one-commit consolidation and full final-head verification; never edit active pipeline-owned branch.
