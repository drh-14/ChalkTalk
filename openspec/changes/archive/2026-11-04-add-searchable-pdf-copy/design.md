# Context and approved direction

The user chose an unchanged-looking PDF with invisible selectable/searchable text. The current pipeline saves normalized text only and deletes rendered page images. It cannot reconstruct a trustworthy overlay from stored text. The frontend has no PDF viewer. All original-byte downloads are attachments and must remain unchanged.

The architect recommends a raster-derived searchable copy for this demo: `pdftoppm` renders the visible cropped/rotated page, Tesseract normal PDF output combines that image with an aligned invisible text layer, and qpdf assembles the pages. This avoids fragile transforms between OCR coordinates and source CropBox/Rotate/UserUnit values and avoids duplicated native/OCR text layers. It deliberately does not preserve the source PDF's vector objects or interactive annotations. No original is rewritten. Native browser PDF viewing provides page navigation/search/selection without PDF.js.

# Data and lifecycle

Add `course_file_searchable_pdfs`, keyed by `file_id` with `(course_id,file_id)` foreign key to `course_files` and cascade deletion. Suggested fields: `status` (`pending`, `ready`, `failed`), `generation` UUID, `object_key`, `size_bytes`, `page_count`, bounded internal `failure_code`, `created_at`, `updated_at`. Only ready rows may have an object key and positive size/page count; failed rows carry an internal failure code. Absence is exposed as `not_requested`. Keep object keys and failure codes private. Do not modify `course_file_texts`, search vectors, source object keys or resource versions for this feature.

POST preparation reads/locks the current visible PDF resource and file in a transaction. Ready copies are reused; pending requests are deduplicated. An absent/failed record gets a fresh generation UUID and one `generate_searchable_pdf` job bound to `{fileId,generation}` with three attempts and a generation-specific deduplication key. Retry creates a fresh generation; it must not reset a running job. No mass backfill or automatic regeneration on upload.

Store successful output under a private course/file/generation/attempt-specific key. Upload first; commit metadata only under the current job lease, matching pending generation, and a lock/recheck that the file remains the active revision of a live resource in an active or archived course. A lost lease, replacement, removal or course deletion must not publish a stale copy; delete its just-uploaded object, or durably queue deletion if immediate cleanup fails. Use generation-unique keys so a stale attempt cannot overwrite the winner. Reuse `delete_course_file` for unreferenced orphan-derived keys only after verifying that the existing branch does not delete an active derivative; otherwise add a narrowly scoped general-lane derived-object deletion job.

Extend existing file-retirement/removal cleanup and `deleteCourse()` so derived object keys are removed before their database metadata is cascaded away. Recheck active derivative references before an orphan cleanup. Both the generation completion transaction and cleanup must lock the same file/derivative rows; course deletion's existing course lock prevents a new request from being committed after deletion begins. S3 failures leave durable retryable cleanup work rather than dropping the last key reference. A metadata FK cascade alone is insufficient.

# HTTP contract

Use the existing resource visibility/authorization logic (including staff-only sections, current membership and deleted-user checks) for every route. Current authorized readers, including students, may request a derived copy in active or archived courses; this is not instructor catalog editing.

- `GET /api/v1/courses/{courseId}/resources/{resourceId}/searchable-pdf`: status only, no generation side effects. `200 application/json`, `Cache-Control: private, no-store`. Envelope `{data:{fileId,status,pageCount,sizeBytes,viewUrl,downloadUrl}}`; `status` is `not_requested|pending|ready|failed`; the remaining metadata/URLs are null unless ready. Ready URLs are relative authenticated routes bound to this exact current `fileId`.
- `POST` the same route: authenticated unsafe JSON request with `{}` only, allowed Origin and session CSRF token. Reuse ready output with `200`; enqueue/deduplicate pending generation with `202`. Return the same envelope, private no-store caching and `Location` pointing to the status route. A reader can retry failed generation with this operation. Concurrent requests create only one current pending generation.
- `GET .../searchable-pdf/{fileId}/view`: ready current-generation PDF bytes with `Content-Type: application/pdf`, exact `Content-Length`, safe `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`. Authorize the current resource again and verify its file ID matches the URL. A request bound to a replaced file returns 404.
- `GET .../searchable-pdf/{fileId}/download`: same authorization and bytes, safe attachment filename derived from the original stem plus `-searchable.pdf`.

Missing session is `401 authentication_required`; invalid unsafe Origin/CSRF is 403; missing, hidden, removed, wrong-course, link, non-PDF or inaccessible resources (including a stale fileId) return `404 not_found`; invalid JSON/unknown request fields use the existing JSON/validation error conventions; unavailable service/storage is `503 service_unavailable`. Content requests before ready return `409 searchable_pdf_not_ready`. Do not expose object keys, direct S3 URLs or raw tool errors. Existing original downloads and extracted-text contracts are unchanged.

# Background generator and budgets

Add `generate_searchable_pdf` to the worker's explicit kind type, extraction-lane claim allowlist, two-minute lease condition, dispatch, lease/heartbeat fencing and final-failure handling. Keep it out of the general lane so missing OCR tools pause generation rather than exhaust jobs. Extend the worker tool probe to include qpdf; Poppler/Tesseract are already installed. Reuse the existing 15-minute hard lease-aware work deadline and three-attempt retry policy, except that reaching the deadline fails the generation permanently so an oversized job cannot hold the sequential lane for three attempts; generation must fail rather than publish a partial document.

Download the original into private scratch space. Inspect page count and sizes. Support PDFs only, with at least one page and no more pages than the configured OCR page cap (zero disables generation). Render every page using the existing cropbox, rotation and bounded DPI/4000px-long-side policy. For each page, pass the actual render DPI to Tesseract normal `pdf` output (`--dpi` must be an accepted integer), with configured languages and PSM 3. Store page PDFs, but delete each raster image before rendering the next page. Accumulate file sizes and fail above 100 MiB; also enforce a 100 MiB merged-output cap. Use shell-free tool invocations, existing abort/timeout/output limits, bounded argument lists and private scratch cleanup. qpdf accepts warning-only completion (3) where recovery succeeds, but fatal exits fail. Verify the merged output's page count equals the source count before publishing it.

The derivative represents the rendered crop/rotation and a fresh OCR layer, so it can differ slightly in physical rounding, OCR reading order, text recognition and high-zoom sharpness. It must not claim exact original bytes, vector preservation, perfect table reconstruction, or original native-text exactness. Original download remains the fallback.

# Frontend

Add a **Searchable PDF** view choice to the existing extracted-text panel only for PDF files; pass `mediaType`/file identity from catalog and search-result cards. Keep all card actions compact. Selecting the mode requests status, prepares a copy when needed, and polls only while the panel is open in this mode and generation is pending. Cancel fetches/poll timers when mode/resource/version changes or the panel closes. Poll every two seconds for the first 30 seconds, then every ten seconds, with no concurrent status requests; avoid duplicate POSTs. Stop after 16 minutes of pending responses and replace the preparing status with a taking-longer notice and Check again action. Check again starts a fresh bounded polling cycle for the current resource. Show preparing, failed/retry and ready states without resetting text-view data or edit drafts.

When ready, embed the protected inline URL in a titled `<iframe>`/`<object>` with a useful minimum height, plus **Open searchable PDF** and **Download searchable PDF** links for browsers/mobile that do not embed PDFs. Preserve readable/original text choices and Download .txt. Include one short material limitation as a small caption beneath the embedded viewer (not above the controls): this rendered copy may have less zoom detail; the original PDF is still available. Keep panel vertical spacing compact and consistent (one small gap between heading, layout selector, actions and viewer). Do not add developer implementation details to the normal flow.
